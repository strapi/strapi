1. Vision & product model

One Strapi deployment, one database, one admin shell — many isolated Spaces (workspaces). An agency runs one Strapi for ten client sites; a company runs one Strapi for every brand. Admins switch between spaces from a header dropdown; each space sees only its own content.

The full product model (target state, later phases):

  • A space grants access to specific collection types, single types and components. Some are shared across spaces, some aren't.
  • Webhooks, API tokens, permissions, roles and users are space-specific.
  • The Media Library is split per space.
  • A default space always exists. Assigning a role grants that role's users access to a space (role → space mapping).

The architecture mirrors @strapi/plugin-i18n: where i18n injects a locale dimension into every query, Spaces injects a space dimension.

2. Core concepts

Concept Definition
Workspace A virtual tenant: plugin::spaces.space collection type with slug (unique), name, color, status (active/archived) and previewBaseUrl. What a workspace may do is decided by its users' roles. Hidden from the Content Manager and CTB.
Default workspace "Strapi as it exists today": always present, undeletable, sees every entry, user, content type and setting unfiltered (with a "Workspace" column and filter in the Content Manager). Writes from default target a workspace. Publishing releases, editing the schema, managing workspaces and bindings, and licence surfaces live there.
Workspace-scoped CT Every api:: content type, by default: an injected space relation (a real space_id column). Opt out with pluginOptions.spaces.enabled: false (or scope: 'none'); a plugin type opts in with scope: 'space' (the Media Library models do).
Shared entry A row with space_id IS NULL: visible in every workspace, editable from default only. Per content type (pluginOptions.spaces.sharedEntries, optionally sharedEditable) or per entry (share from the "Workspace" side panel, or POST /spaces/move with targetSpaceSlug: null).
Visibility binding pluginOptions.spaces.visibleIn: string[] — which workspaces a CT appears in. Empty/missing = visible everywhere. Settings resources (roles, tokens, webhooks, locales) use the same convention through a hidden spaces many-to-many; a resource bound to several workspaces (or none) is read-only outside default.
Membership A user belongs to a workspace when bound to it directly (spaces M2M on admin::user), when a role of theirs is bound to it, or when they hold a platform-wide role; super admins belong everywhere. A request carrying a workspace the user is not a member of is refused.
Active workspace Per-request state resolved from the X-Strapi-Space-Id header (slug). No header = platform view (CLI, bootstrap, cron): no filter.

4. Storage model

  • Workspaces table — spaces (from the plugin CT).
  • Scoped CTs — the injected relation is manyToOne with useJoinTable: false, so each scoped table gains a real space_id column (no join table). The attribute is private: API consumers never read or write it directly. NULL = shared with every workspace, after a one-time backfill attached the rows that predate workspaces to default (idempotency tracked in the plugin store, never re-derived from IS NULL).
  • Referencing rows — release actions, content history versions and audit logs carry the same space_id column: the entry's workspace for the first two, the workspace the action was performed in for audit logs.
  • Settings resources and users — a hidden spaces manyToMany per resource (link table), where zero link rows = platform-wide. Users have one too (direct membership).
  • Per-workspace default locale — i18n core store keys default_locale_<spaceSlug>, falling back to the global default_locale. The last-used workspace of a user lives in the plugin store.
  • Uninstall — schema sync never drops columns or tables without forceMigration, and the plugin tables are persisted (EE): default reverts to full visibility, nothing is deleted.

5. Request lifecycle

  1. The admin (or an API consumer) sends X-Strapi-Space-Id: acme.
  2. resolve-space loads the workspace row; 400 on unknown/archived; sets ctx.state.spaceId + ctx.state.spaceSlug.
  3. Authentication wrappers: a bound API token only operates inside its workspaces; an admin who is not a member of the workspace is refused (403), except on the self-service routes the switcher needs to recover.
  4. Koa integrations: default-only rules (schema writes, release publishing, workspace management), content-type visibility, and the settings scoping / read-only rules.
  5. The document-service middleware decides, per operation, which workspace the entry belongs to: creates are stamped (forced to the caller's workspace outside default; from default the body's space or default), updates/deletes/publishes look the entry up across workspaces and refuse what the caller may not edit (403 for a shared entry, 404 for another workspace's), then run inside runScoped(workspace).
  6. The DB read net filters every findOne/findMany/count on a scoped model: a sub-workspace sees space_id = X OR space_id IS NULL; default, headerless callers and runUnscoped() blocks are unfiltered. User filters are ANDed underneath. Because writes run inside a scope, the validator's uniqueness query sees the same rows: unique fields are unique per workspace.
  7. Raw strapi.db.query() writes that skip the document service are caught by the beforeCreate stamp and the beforeUpdate/beforeDelete refusal.

6. The settings-visibility pattern

Settings resources (locales today; API tokens, transfer tokens, webhooks, media folders next) are defined once and made visible in N spaces. Three reusable helpers in settings-visibility/index.ts:

  1. injectVisibilityRelation(strapi, uid) — register-time; hidden spaces M2M on the resource CT.
  2. wrapControllerForVisibility(strapi, opts) — bootstrap-time Koa middleware around the host plugin's create/update routes. Extracts spaces: string[] (and extra fields like defaultIn) from the body before the host's strict Yup validation rejects them, lets the original controller run, then writes the M2M rows. Includes a validateRemoval pre-check that 400s before the host controller runs (atomicity) and normalizes "explicitly all spaces checked" to the empty (platform-wide) binding.
  3. scopeReadByCurrentSpace(strapi, service, methods) — bootstrap-time read wrapper: filters rows to spaces.slug = active OR spaces empty, auto-populates spaces on results. Bypasses: ?scope=all (settings pages) and runUnscoped() (AsyncLocalStorage-based, for internal code that needs global reads such as permission syncs).
Why a Koa middleware, not a controller monkey-patch? Strapi.bootstrap() runs initRouting() before plugin bootstrap hooks, and route composition binds controller methods — a later swap is never observed. Koa middleware registered via strapi.server.use() in bootstrap is picked up because the router mounts lazily at listen time.

7. i18n integration

All wired from the spaces side (i18n-integration.ts), guarded by strapi.plugin('i18n') checks:

  • Read scope — locales.find/count wrapped; findByCode re-implemented via the wrapped find.
  • Write scope — create/update locale routes wrapped; the validateRemoval hook refuses removing a locale from a space where it's still load-bearing (space's default locale, or entries in that space use it).
  • Per-space default — a default-locale strategy installed through i18n's extension hook localesService.setDefaultLocaleStrategy() (added to i18n for this): get/set/isDefault resolve per-space override → platform default → first visible locale (self-healing), and listDefaults() feeds the isDefaultIn: string[] arrays the Settings table renders.
  • Permission-sync fix — i18n's syncSuperAdminPermissionsWithLocales re-implemented to run under runUnscoped() (otherwise a locale created inside a tenant view would rewrite super-admin permissions with a space-filtered locale list) and to skip orphan permission rows instead of aborting.

On the admin side, i18n exposes two extension points (admin/src/i18n-plugin.ts): registerLocaleFormExtension (extra form sections in the locale create/edit modal) and registerLocaleTableColumn (extra Settings-table columns). The spaces plugin registers its "Available in spaces" / "Default in spaces" fields and the two chip columns through them — i18n has zero dependency on spaces.

8. Moving entries between spaces

POST /spaces/move · body { uid, documentIds[], targetSpaceSlug } · gated by the plugin::spaces.move-entry RBAC action. Validation order:

  1. CT exists and is space-scoped.
  2. Target space exists and is active.
  3. Target space is in the CT's visibleIn binding.
  4. For localized CTs: every locale carried by the source rows must be available in the target space (otherwise the move would orphan translations).
The move deliberately bypasses the document service and writes the space FK via strapi.db.query() in a single transaction: the multitenancy middleware would otherwise filter the source rows out of reach (they belong to another space than the caller's active one).

Admin surfaces: a header action on the edit view (navigates back to the list on success — the document no longer exists in the current space) and a bulk action on the list view (invalidates the CM's RTK Query caches instead of reloading).

9. Isolation guarantees

# Guarantee Mechanism
1 A sub-workspace never reads another workspace's rows, through any read path. The DB read net on every scoped model (document service and raw db.query alike); user filters are ANDed and cannot widen the view.
2 A sub-workspace never writes what it may not edit. Document-service middleware (403 shared entry / shared type, 404 other workspace) + beforeUpdate/beforeDelete lifecycle refusal for raw single-row writes.
3 Every row is stamped with the right workspace, even on raw-DB bypass paths. Middleware (canonical) + beforeCreate lifecycle (precedence: explicit value, scope override, shared type, request workspace).
4 An invalid or unauthorised workspace selector fails loudly. resolve-space 400s on unknown/archived slugs; the membership guard 403s non-members; bound API tokens cannot leave their workspaces.
5 Shared settings cannot be altered from a sub-workspace. Platform-wide or multi-bound roles/tokens/webhooks/locales are read-only there (permissions, regeneration and triggering included); bindings are edited from default only.
6 Grants are bounded by the grantor. The RBAC ceiling (core): no permission can be granted that the caller does not hold.
—
Not guaranteed: nested populates through inverse relations bypass the lifecycles (a generic query-filter hook is the fix), GraphQL, and the content API without a header (platform view by design).

10. Key design decisions

  1. params.filters, not params.lookup — i18n uses lookup, but validateParams throws on unknown lookup keys for third-party dimensions (document-service/repository.ts). Filters are validated against the schema, and the injected space relation makes them legal.
  2. space_id join column, no join table — manyToOne + useJoinTable: false. Cheap filtering, obvious raw-SQL debugging.
  3. Relation descriptors are factories — Strapi mutates attribute metadata during registration; sharing one descriptor object across CTs makes one CT's link table silently steal another's writes. Learned the hard way.
  4. Empty binding = platform-wide — shared convention for CT visibleIn and settings M2Ms; new spaces automatically inherit platform-wide resources. "Explicitly all checked" normalizes to empty at write time.
  5. AsyncLocalStorage-based runUnscoped() — survives async boundaries without leaking across concurrent requests; used by internal enumerations (permission sync, listDefaults).
  6. Move bypasses the document service — see §8.
  7. pluginOptions.spaces.*, not options.multiTenancy — plugin options live under the plugin's namespace (mirrors pluginOptions.i18n.localized), keeping core CTB byte-identical when the plugin isn't installed. (Older README/comment references to options.multiTenancy are stale.)
  8. Space header carries the slug — human-readable in curl and logs; numeric id accepted as a fallback.

12. Known risks & gotchas

  • Backfill semantics — after v2, NULL means shared. The backfill must never be re-derived from IS NULL: its idempotency marker lives in the plugin store. Legacy Media Library assets end up in default (share them from there).
  • Turning sharedEntries off on a type with rows flips semantics without a migration: stamped rows become exclusive again, NULL rows stay shared (the CTB hint says so).
  • Edit-view lock is asynchronous — the admin RBAC middleware fetches the entry state; the server refusal is the guarantee. The switcher leaves an edit view on a workspace change because the RBAC hook does not re-run on pathname changes.
  • Nested populates bypass lifecycles: inverse relations from default can surface other workspaces' rows to a sub-workspace through a nested populate.
  • Refusals must be PolicyErrors — the endpoint composer masks any other ForbiddenError thrown by a controller into a bare 403.
  • Bulk updates through relation filters — the query builder cannot updateMany through a join; the backfill updates the column on the connection.
  • i18n locale isolation — moving a localized entry to a workspace that can't surface its locale would orphan it; guarded in the move service and in validateRemoval.
  • Bound controller references — bootstrap-time controller swaps are never observed (see §6); always go through route middleware or patch the registered service object.
  • Preview origins — frame-src stays the static union of allowedOrigins; list every workspace's origin there.
