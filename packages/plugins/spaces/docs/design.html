1. Vision & product model

One Strapi deployment, one database, one admin shell — many isolated Spaces (workspaces). An agency runs one Strapi for ten client sites; a company runs one Strapi for every brand. Admins switch between spaces from a header dropdown; each space sees only its own content.

The full product model (target state, later phases):

  • A space grants access to specific collection types, single types and components. Some are shared across spaces, some aren't.
  • Webhooks, API tokens, permissions, roles and users are space-specific.
  • The Media Library is split per space.
  • A default space always exists. Assigning a role grants that role's users access to a space (role → space mapping).

The architecture mirrors @strapi/plugin-i18n: where i18n injects a locale dimension into every query, Spaces injects a space dimension.

2. Core concepts

Concept Definition
Space A virtual tenant: plugin::spaces.space collection type with slug (unique), name, color, status (active/archived). Hidden from the Content Manager and CTB.
Space-scoped CT A content type opting in via pluginOptions.spaces.scope: 'space' in its schema.json. Its entries are partitioned per space through an injected space relation (a real space_id FK column).
Platform CT Any CT without the opt-in (or scope: 'platform'). Shared across every space, untouched by the plugin.
Visibility binding pluginOptions.spaces.visibleIn: string[] — which spaces a CT appears in. Empty/missing = visible everywhere. The same convention applies to settings resources (locales today) via a hidden spaces many-to-many.
Active space Per-request state resolved from the X-Strapi-Space-Id header (slug). No header = platform view: no tenant filter.

4. Storage model

  • Spaces table — spaces (from the plugin CT).
  • Scoped CTs — the injected relation is manyToOne with useJoinTable: false, so each scoped table gains a real space_id column (no join table). The attribute is private: API consumers never read or write it directly.
  • Settings resources — a hidden spaces manyToMany per resource (link table), where zero link rows = platform-wide.
  • Per-space default locale — i18n core store keys default_locale_<spaceSlug>, falling back to the global default_locale.

5. Request lifecycle

  1. The admin (or an API consumer) sends X-Strapi-Space-Id: acme.
  2. resolve-space loads the space row; 400 on unknown/archived; sets ctx.state.spaceId + ctx.state.spaceSlug.
  3. Controllers call the document service; the multitenancy middleware reads the request context (strapi.requestContext) and injects the tenant dimension:
    • Reads (findMany/findOne/findFirst/findPage/count/clone): params.filters.space = { id } — deliberately clobbering any user-supplied space filter.
    • Writes (create/update): params.data.space = id when absent.
  4. Raw strapi.db.query() writes that skip the document service are caught by the beforeCreate lifecycle subscriber.
  5. No header → steps 3–4 are no-ops (platform view).

6. The settings-visibility pattern

Settings resources (locales today; API tokens, transfer tokens, webhooks, media folders next) are defined once and made visible in N spaces. Three reusable helpers in settings-visibility/index.ts:

  1. injectVisibilityRelation(strapi, uid) — register-time; hidden spaces M2M on the resource CT.
  2. wrapControllerForVisibility(strapi, opts) — bootstrap-time Koa middleware around the host plugin's create/update routes. Extracts spaces: string[] (and extra fields like defaultIn) from the body before the host's strict Yup validation rejects them, lets the original controller run, then writes the M2M rows. Includes a validateRemoval pre-check that 400s before the host controller runs (atomicity) and normalizes "explicitly all spaces checked" to the empty (platform-wide) binding.
  3. scopeReadByCurrentSpace(strapi, service, methods) — bootstrap-time read wrapper: filters rows to spaces.slug = active OR spaces empty, auto-populates spaces on results. Bypasses: ?scope=all (settings pages) and runUnscoped() (AsyncLocalStorage-based, for internal code that needs global reads such as permission syncs).
Why a Koa middleware, not a controller monkey-patch? Strapi.bootstrap() runs initRouting() before plugin bootstrap hooks, and route composition binds controller methods — a later swap is never observed. Koa middleware registered via strapi.server.use() in bootstrap is picked up because the router mounts lazily at listen time.

7. i18n integration

All wired from the spaces side (i18n-integration.ts), guarded by strapi.plugin('i18n') checks:

  • Read scope — locales.find/count wrapped; findByCode re-implemented via the wrapped find.
  • Write scope — create/update locale routes wrapped; the validateRemoval hook refuses removing a locale from a space where it's still load-bearing (space's default locale, or entries in that space use it).
  • Per-space default — a default-locale strategy installed through i18n's extension hook localesService.setDefaultLocaleStrategy() (added to i18n for this): get/set/isDefault resolve per-space override → platform default → first visible locale (self-healing), and listDefaults() feeds the isDefaultIn: string[] arrays the Settings table renders.
  • Permission-sync fix — i18n's syncSuperAdminPermissionsWithLocales re-implemented to run under runUnscoped() (otherwise a locale created inside a tenant view would rewrite super-admin permissions with a space-filtered locale list) and to skip orphan permission rows instead of aborting.

On the admin side, i18n exposes two extension points (admin/src/i18n-plugin.ts): registerLocaleFormExtension (extra form sections in the locale create/edit modal) and registerLocaleTableColumn (extra Settings-table columns). The spaces plugin registers its "Available in spaces" / "Default in spaces" fields and the two chip columns through them — i18n has zero dependency on spaces.

8. Moving entries between spaces

POST /spaces/move · body { uid, documentIds[], targetSpaceSlug } · gated by the plugin::spaces.move-entry RBAC action. Validation order:

  1. CT exists and is space-scoped.
  2. Target space exists and is active.
  3. Target space is in the CT's visibleIn binding.
  4. For localized CTs: every locale carried by the source rows must be available in the target space (otherwise the move would orphan translations).
The move deliberately bypasses the document service and writes the space FK via strapi.db.query() in a single transaction: the multitenancy middleware would otherwise filter the source rows out of reach (they belong to another space than the caller's active one).

Admin surfaces: a header action on the edit view (navigates back to the list on success — the document no longer exists in the current space) and a bulk action on the list view (invalidates the CM's RTK Query caches instead of reloading).

9. Isolation guarantees

# Guarantee Mechanism
1 Reads through the document service never return another space's rows. Multitenancy middleware force-merges the filter, clobbering user-supplied space filters.
2 Writes are stamped with the active space even on raw-DB bypass paths. Middleware (canonical) + beforeCreate lifecycle subscriber (safety net).
3 An invalid tenant selector fails loudly. resolve-space 400s on unknown/archived slugs instead of silently serving platform data.
—
Not yet guaranteed: reads via raw strapi.db.query() (a beforeFindMany/beforeFindOne/beforeCount net is deferred), GraphQL, and the content API without a header (platform view by design in phase 1).

10. Key design decisions

  1. params.filters, not params.lookup — i18n uses lookup, but validateParams throws on unknown lookup keys for third-party dimensions (document-service/repository.ts). Filters are validated against the schema, and the injected space relation makes them legal.
  2. space_id join column, no join table — manyToOne + useJoinTable: false. Cheap filtering, obvious raw-SQL debugging.
  3. Relation descriptors are factories — Strapi mutates attribute metadata during registration; sharing one descriptor object across CTs makes one CT's link table silently steal another's writes. Learned the hard way.
  4. Empty binding = platform-wide — shared convention for CT visibleIn and settings M2Ms; new spaces automatically inherit platform-wide resources. "Explicitly all checked" normalizes to empty at write time.
  5. AsyncLocalStorage-based runUnscoped() — survives async boundaries without leaking across concurrent requests; used by internal enumerations (permission sync, listDefaults).
  6. Move bypasses the document service — see §8.
  7. pluginOptions.spaces.*, not options.multiTenancy — plugin options live under the plugin's namespace (mirrors pluginOptions.i18n.localized), keeping core CTB byte-identical when the plugin isn't installed. (Older README/comment references to options.multiTenancy are stale.)
  8. Space header carries the slug — human-readable in curl and logs; numeric id accepted as a fallback.

12. Known risks & gotchas

  • i18n locale isolation — moving a localized entry to a space that can't surface its locale would orphan it; guarded in the move service and in validateRemoval.
  • Sanitizer vs. populated bindings — the content-API sanitizer strips private attributes; the locale spaces M2M is deliberately private: false so the Settings UI can round-trip it.
  • Bound controller references — bootstrap-time controller swaps are never observed (see §6); always go through route middleware.
  • Raw-DB reads — not yet filtered; plugins doing strapi.db.query().findMany() on scoped CTs see every space until the read net lands.
  • Per-request space resolution — one indexed DB lookup per request carrying the header; add caching if it ever shows up in profiles.
  • Platform view is unauthenticated-by-design in phase 1 — any admin (and any content-API consumer omitting the header) sees all spaces until phase 4's role → space mapping lands.
